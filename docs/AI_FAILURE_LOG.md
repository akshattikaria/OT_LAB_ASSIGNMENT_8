# Actual AI-assisted development failures

These are observed implementation/efficiency errors, not deliberately created mutation faults. Older tracks have their own genuine failure records; this file does not invent mistakes to meet the assignment's minimum.

## J1 — Child collected the wrong tests directory

The original child runner inserted the vendor source path but invoked pytest on relative `tests` while still in the project root. That referred to the new host-test folder rather than the cachetools distribution's tests. The initial pilot exited with pytest code 5 and no collected tests. Source pinning and a correct import path alone were insufficient to establish that the intended suite had actually run.

Evidence: `validation/coverage_pilot.log`, `docs/initial_cwd_failure.log`, and the pilot `run.json`/matrix. The failure is retained in commit `c4ed2ab`.

Fix: resolve subject/output/node-list paths before changing directory, then run the child from the vendor root. Assert that the imported package path is inside that subject. Add a real subprocess regression from the project root that checks all 391 intended parent tests pass. The fix is commit `b80da3e`; ten final host tests include this regression. Fresh coverage and replay evidence confirm the target suite.

Lesson: verify collected test identities and package provenance, not only a command's exit status.

## J2 — Redundant context expansion produced huge coverage JSON

The initial fixed pilot requested `show_contexts=True` in the coverage JSON report while already saving the context SQLite database and per-test incidence matrix. Context information was repeated in file/function/class sections: the initial JSON was about 171 MiB and temporary report files reached hundreds of MiB together. This is an inefficient artifact design for a small CI experiment, and added unnecessary serialization cost.

Evidence: the original large report and temporary files are retained in the historical commits `b80da3e` and `ba623ad`. The final working snapshot removes temporary serialization fragments and keeps a compact summary for the early pilot. Its SQLite database and incidence matrix remain intact. The final baseline and selected suites use `show_contexts=False`, retaining their full context evidence in SQLite and the explicit matrix; their standard JSON summaries remain directly generated by coverage.

Fix: disable redundant JSON context expansion. Retain file-level summaries for the early pilot and remove only its temporary report fragments. Commit `ba623ad` contains the configuration fix; the cleanup/documentation commit is listed in COMMIT_INDEX.md. The audit independently reconstructs all four final incidence matrices from SQLite.

Lesson: save each large measurement representation deliberately. Full experimental evidence does not require repeating the same context matrix in several nested report formats.
